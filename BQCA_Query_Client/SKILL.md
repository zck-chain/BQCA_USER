# BQCA 电商数据查询

调用接口：`POST` 请求。

### 服务端接口地址：
* **生产环境 (Production)**：`https://bqca-bot-839062387451.asia-east1.run.app/api/query`

服务端根据角色选择对应 Service Account，绝不在请求、回答或本技能文件中包含 API Key。

## 角色与会话

- 支持角色：`运营经理`、`一线客服`。
- 主动识别角色：经理、管理员对应运营经理；客服、物流对应一线客服。
- 首次出现业务问题但未说明角色时，先询问“请问你的角色是运营经理还是一线客服？”，不要调用服务。
- 用户只说明角色或说“切换为客服/经理”时，调用服务更新角色，但不查询 BQCA。
- 保存服务返回的 `session_id`，并在之后每次请求中携带它。
- 每次查询都携带当前角色。若服务端会话过期或切换实例，服务端会以该角色创建新会话。
- `conversation_id` 仅用于结果追踪；服务端按 `session_id` 管理 BQCA 多轮会话，不要把它传回请求。

## 请求

首次设置角色，不带业务问题：

```json
{"role": "一线客服"}
```

首次说明角色并查询：

```json
{"question": "商品状态分布", "role": "一线客服"}
```

后续追问：

```json
{
  "question": "已发货商品有多少件？",
  "role": "一线客服",
  "session_id": "上次返回的session_id"
}
```

切换角色：

```json
{
  "role": "运营经理",
  "session_id": "上次返回的session_id"
}
```

## 响应

### 1. 切换/初始化角色成功响应：
当发送仅含 `role` 的请求或角色成功切换时，返回如下结构：
```json
{
  "message": "已切换为一线客服",
  "session_id": "您的当前会话ID_session_id",
  "conversation_id": "projects/...",
  "role": "一线客服"
}
```

### 2. 标准数据查询成功响应：
当发送业务 `question` 进行查询并获取结果时，返回包含决策洞察、SQL 和明细数据的结构：
```json
{
  "summary": "业务决策洞察文本段落...",
  "sql": "SELECT ...",
  "fields": ["col1", "col2"],
  "rows": [{"col1": "val1", "col2": "val2"}],
  "chart": true,
  "html_url": null,
  "session_id": "您的当前会话ID_session_id",
  "conversation_id": "projects/...",
  "role": "一线客服"
}
```

### 3. 服务端异常处理字典 (HTTP 400 错误映射)：
当调用方收到 **`HTTP 400 Bad Request`** 响应时，应根据返回的 `detail` 错误文本执行以下智能自愈逻辑：

* **`"role is required for a new session"`**：
  * **原因**：会话已过期、未初始化、或服务端重启导致角色绑定失效。
  * **自愈方案**：立即向用户索要角色（“*请问您的角色是运营经理还是一线客服？*”），获取输入后携带角色参数重新重试。
* **`"unsupported role"`**：
  * **原因**：传入的 `role` 字符串未包含在预设别名或标准角色中（如传入了“总经理”）。
  * **自愈方案**：提示用户：“*抱歉，该角色暂无权限。请明确选择我是【运营经理】还是【一线客服】。*” 引导其输入合规身份后重试。
* **`"question is required"`**：
  * **原因**：请求中未提供 `question` 字段，且不属于合规的角色切换请求。
  * **自愈方案**：检查并在请求体中补全用户的业务问题字段。

## 结果展示与交互规范

- **角色归一化记忆**：虽然接口支持别名输入（如输入“经理”），但服务端在响应中始终会返回归一化的标准角色值（`"运营经理"` 或 `"一线客服"`）。调用方应以返回的归一化标准值更新其内部会话状态。
- **优先用数据呈现**：优先用 `fields` 和 `rows` 生成直观的数据表格，并搭配最底部的核心直接结论进行回答。
- **简单事实查询**：直接结论、简短表格、可信依据。
- **分布或对比查询**：表格、必要占比或趋势、简短洞察、可信依据。
- **可信依据声明**：每个查询结果最末尾，至少声明一次“当前运行角色、对应权限范围、以及查询所关联的口径与行数”。
- **仅在要求时审计**：仅在用户要求审计或计算口径异常复杂时展示 `sql` 字段内容；仅在 `html_url` 有值时展示链接。
- **客服合规提示**：当角色为 `一线客服` 时，回答最顶部或最尾部必须醒目提示：*“⚠️ 当前已为您切换为一线客服视图，由于地区数据隔离合规要求，您仅拥有美国地区（United States）相关用户、订单及商品数据的查询权限。”*
- **空结果与异常退路**：返回空行代表没有匹配数据。若接口报错或网络失败，请简短说明服务或权限暂不可用，不要自我编造查询结果。
