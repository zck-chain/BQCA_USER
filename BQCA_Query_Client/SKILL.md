# BQCA 电商数据查询

调用接口：`POST` 请求。

### 服务端接口地址：
* **生产环境 (Production)**：`https://bqca-bot-839062387451.asia-east1.run.app/api/query`
* **本地开发 (Local Debugging)**：`http://127.0.0.1:8080/api/query` 或您部署调试对应的 `ngrok` 公网映射隧道地址

服务端根据角色选择对应 Service Account，绝不在请求、回答或本技能文件中包含 API Key。

## 角色与会话

- 支持角色：`运营经理`、`一线客服`。
- 主动识别角色：经理、管理员对应运营经理；客服、物流对应一线客服。
- 首次出现业务问题但未说明角色时，先询问“请问你的角色是运营经理还是一线客服？”，不要调用服务。
- 用户只说明角色或说“切换为客服/经理”时，调用服务更新角色，但不查询 BQCA。
- 保存服务返回的 `session_id`，并在之后每次请求中携带它。
- 每次查询都携带当前角色。若服务端会话过期或切换实例，服务端会以该角色创建新会话。
- `conversation_id` 仅用于结果追踪；服务端按 `session_id` 管理 BQCA 多轮会话，不要把它传回请求。

## 请求

首次设置角色，不带业务问题：

```json
{"role": "一线客服"}
```

首次说明角色并查询：

```json
{"question": "商品状态分布", "role": "一线客服"}
```

后续追问：

```json
{
  "question": "已发货商品有多少件？",
  "role": "一线客服",
  "session_id": "上次返回的session_id"
}
```

切换角色：

```json
{
  "role": "运营经理",
  "session_id": "上次返回的session_id"
}
```

## 响应

### 1. 切换/初始化角色成功响应：
当发送仅含 `role` 的请求或角色成功切换时，返回如下结构：
```json
{
  "message": "已切换为一线客服",
  "session_id": "您的当前会话ID_session_id",
  "conversation_id": "projects/...",
  "role": "一线客服"
}
```

### 2. 标准数据查询成功响应：
当发送业务 `question` 进行查询并获取结果时，返回包含决策洞察、SQL 和明细数据的结构：
```json
{
  "summary": "业务决策洞察文本段落...",
  "sql": "SELECT ...",
  "fields": ["col1", "col2"],
  "rows": [{"col1": "val1", "col2": "val2"}],
  "chart": true,
  "html_url": null,
  "session_id": "您的当前会话ID_session_id",
  "conversation_id": "projects/...",
  "role": "一线客服"
}
```

### 3. 会话失效或角色缺失响应 (异常处理)：
* 服务端返回新的 `session_id` 时，用新值替换旧值。
* 若服务返回 **`HTTP 400 Bad Request`** 且 detail 报错为 **`"role is required for a new session"`**，代表会话已过期或没有绑定的有效角色。调用方应立即向用户询问角色：“*请问您的角色是运营经理还是一线客服？*”，获取输入后携带角色参数重新重试。

## 结果展示

- 优先用 `fields` 和 `rows` 生成数据表格与直接结论。
- 简单事实查询：直接结论、简短表格、可信依据。
- 分布或对比查询：表格、必要占比或趋势、简短洞察、可信依据。
- 可信依据至少说明当前角色 and 权限范围、查询口径、返回行数或总数。
- 仅在用户要求审计或口径复杂时展示 `sql`；仅在 `html_url` 有值时展示链接。
- 一线客服必须提示：当前仅展示已发货（Shipped）相关数据。
- 空结果：说明没有匹配数据。网络失败、服务错误 or 401/403：简短说明服务或权限暂不可用，不要编造结果。
