# BQCA 电商数据查询

> [!IMPORTANT]
> **集成配置指南 (HTTP 超时设置)：**
> 由于本服务涉及大模型自然语言 SQL 语义翻译、GCP 服务账号扮演安全鉴权以及 BigQuery 数仓的物理数据执行，单次完整调用耗时通常在 **10 ~ 15 秒** 左右。
> 
> 在将此技能导入至 **Dify、Coze、Custom GPTs (Actions)** 或其他智能体平台时，请务必在工具/动作的高级设置中，将该 API 的 **HTTP 请求超时时间 (HTTP Timeout) 配置为不低于 30 秒（推荐 60 秒）**，否则会因为平台默认的 10 秒超时而导致连接中断报错。

调用服务：`POST https://exemption-wizard-seclusion.ngrok-free.dev/api/query`。

服务端根据角色选择对应 Service Account，绝不在请求、回答或本技能文件中包含 API Key。

## 角色与会话

- 支持角色：`运营经理`、`一线客服`。
- 主动识别角色：经理、管理员对应运营经理；客服、物流对应一线客服。
- 首次出现业务问题但未说明角色时，先询问“请问你的角色是运营经理还是一线客服？”，不要调用服务。
- 用户只说明角色或说“切换为客服/经理”时，调用服务更新角色，但不查询 BQCA。
- 保存服务返回的 `session_id`，并在之后每次请求中携带它。
- 每次查询都携带当前角色。若服务端会话过期或切换实例，服务端会以该角色创建新会话。
- `conversation_id` 仅用于结果追踪；服务端按 `session_id` 管理 BQCA 多轮会话，不要把它传回请求。

## 请求

首次设置角色，不带业务问题：

```json
{"role": "一线客服"}
```

首次说明角色并查询：

```json
{"question": "商品状态分布", "role": "一线客服"}
```

后续追问：

```json
{
  "question": "已发货商品有多少件？",
  "role": "一线客服",
  "session_id": "上次返回的session_id"
}
```

切换角色：

```json
{
  "role": "运营经理",
  "session_id": "上次返回的session_id"
}
```

服务端返回新的 `session_id` 时，用新值替换旧值。若返回“需要角色”，重新询问角色后带角色重试。

## 结果展示

- 优先用 `fields` 和 `rows` 生成数据表格与直接结论。
- 简单事实查询：直接结论、简短表格、可信依据。
- 分布或对比查询：表格、必要占比或趋势、简短洞察、可信依据。
- 可信依据至少说明当前角色和权限范围、查询口径、返回行数或总数。
- 仅在用户要求审计或口径复杂时展示 `sql`；仅在 `html_url` 有值时展示链接。
- 一线客服必须提示：当前仅展示已发货（Shipped）相关数据。
- 空结果：说明没有匹配数据。网络失败、服务错误或 401/403：简短说明服务或权限暂不可用，不要编造结果。
